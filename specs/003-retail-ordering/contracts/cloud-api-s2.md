# Cloud API — Slice 2 (migration `2026-10-23_retail_ordering_s2.sql`)

Postgres functions on the Supabase project. Conventions follow 001, 002 and Slice 1:
- **Function shape:** `LANGUAGE plpgsql`, `SECURITY DEFINER`, `SET search_path = public`.
- **Grants:**
  - every function: `REVOKE ALL … FROM PUBLIC`;
  - public functions: `GRANT EXECUTE … TO anon, authenticated`;
  - owner functions: `GRANT … TO authenticated` only;
  - `_`-prefixed internal helpers: revoked from `PUBLIC`, `anon` and `authenticated`.
- **Re-runnable:** the file is safe to run twice. `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`,
  `CREATE OR REPLACE`, and `DROP POLICY IF EXISTS` before `CREATE POLICY`.
- **Results:** functions return `jsonb` with `ok boolean` and `code text` (never `RAISE` for expected refusals) plus
  the payload.

Tables, columns and the state machine are in [data-model-s2.md](../data-model-s2.md).

## Internal helpers

| Function | Purpose |
|---|---|
| `_gateway_ok(p_key text) → boolean` | `true` when `encode(digest(p_key,'sha256'),'hex')` matches a non-revoked row of `storefront_gateway_keys` |
| `_order_phone(p text) → text` | digits-only normalisation matching `storefront/src/phone.ts` (7–8 local digits → `961…`); returns `+<digits>` or null if not 8–15 digits |
| `_order_quote(p_store uuid, p_lines jsonb) → jsonb` | the shared validation and pricing routine (research R14); returns `{lines:[…], total_usd, total_local, local:{code,rate}, problems:[{line, code}]}` |
| `_orders_expire(p_tenant uuid) → integer` | moves the tenant's overdue `submitted` orders to `expired`, writing history (R17) |
| `_order_event(...)` | inserts one history row |
| `_order_owner(p_order uuid) → orders` | the order row `FOR UPDATE` if `tenant_id = auth.uid()`, else null |
| `_order_public(o orders) → jsonb` | the public view (below) |

`_order_quote` line problems: `listing_unavailable`, `unit_not_orderable`, `out_of_stock`, `invalid_quantity`,
`below_listing_minimum`, `price_changed` (the last only when the caller sent the price it showed).

Order-level problems: `too_many_lines`, `below_store_minimum`, `fulfilment_unavailable`.

## Public functions (anon + authenticated; every call needs the gateway key)

Every public function first checks `_gateway_ok(p_gateway)`. Without a valid key it returns `{ok:false, code:'gateway'}`
and touches nothing.

### `order_quote(p_gateway text, p_slug text, p_lines jsonb) → jsonb`

`p_lines` = `[{ listing: uuid, unit: 'base'|uuid, qty: number, price?: number }]` (≤ 50).

Steps:
1. Resolve the store through `_store_public_store(p_slug, null)`.
2. Require `ordering_mode = 'online'` and pickup or delivery on.
3. Run `_order_quote`.

Returns:
- `{ok:true, code:'ok', quote}`;
- `{ok:false, code:'store_unavailable'}`.

Read-only.

### `order_submit(p_gateway, p_slug, p_idempotency text, p_status_key text, p_network text, p_customer jsonb, p_lines jsonb, p_expected_total_usd numeric, p_trap text) → jsonb`

`p_status_key` is generated by the browser: 32 characters `[A-Za-z0-9_-]`, otherwise `invalid` with field
`status_key`. Only its SHA-256 is stored.

`p_customer` = `{ name, phone, fulfilment: 'pickup'|'delivery', address?, note? }`.

Order of checks (research R16):

| Step | Check | Result |
|---|---|---|
| 1 | Gateway key | `gateway` |
| 2 | Store gate + online mode | `store_unavailable` |
| 3 | `_orders_expire(tenant)` | — |
| 4 | Idempotency: an order with `(store, p_idempotency)` already exists | if `p_status_key` hashes to its `status_key_hash` → `{ok:true, code:'existing', number, order}` (the browser already holds the key); otherwise `{ok:false, code:'refused'}` (someone else's attempt key) |
| 5 | `p_trap` not empty | `refused` |
| 6 | Field validation | `invalid` + `field` (`name`, `phone`, `address`, `note`, `fulfilment`) |
| 7 | Phone on the store's blocked list | `refused` |
| 8 | Phone limits (≤ 5 per hour, ≤ 3 in `submitted`, per store) | `phone_limit` |
| 9 | Network limits (≤ 10 per hour per store, ≤ 30 per hour across all stores) | `network_limit` |
| 10 | `_order_quote`: any problem, or a total ≠ `p_expected_total_usd`, or a line price ≠ the sent price | `{ok:false, code:'changed', quote}` |
| 11 | Insert the order (number from `order_counters`, `status_key_hash` = SHA-256 of `p_status_key`, `expires_at` from the setting) and its lines, plus a `submitted` event | `{ok:true, code:'created', number:'W-1042', order:<public view>}` |

Step 11 runs in the function's transaction. A unique-violation race on the idempotency key returns `existing`.

### `order_status(p_gateway, p_status_key text) → jsonb`

Looks the order up by `encode(digest(p_status_key,'sha256'),'hex')`, runs `_orders_expire(tenant)` first, and returns
`{ok:true, order:<public view>}` or `{ok:false, code:'not_found'}`.

### `order_cancel(p_gateway, p_status_key) → jsonb`

Customer cancellation. It runs only from `submitted`, and sets `state = 'cancelled'`, `cancelled_by = 'customer'` and
an event.

Returns:
- `{ok:true, code:'cancelled', order}`;
- `{ok:false, code:'not_cancellable', order}` once the order is accepted or closed;
- `not_found`.

### Public view (`_order_public`)

The public view contains:
- `number`, `state` (effective), `reason` (rejected / shop-cancelled only), `cancelled_by`;
- `first_name` (first word of `customer_name`), `fulfilment`, `address` (delivery only);
- `submitted_at`, `confirmed_at`, `ready_at`, `closed_at`;
- `lines[]`: `product_name`, `unit_name`, `ordered_qty`, `confirmed_qty`, `shortfall_reason`, `unit_price_usd`,
  `unit_price_local`, `line_total_usd`, `line_total_local`;
- `total_usd`, `total_local`, `confirmed_total_usd`, `confirmed_total_local`, `local_currency`;
- `store`: `slug`, `name`, contact (WhatsApp, phone, email as public in 002).

It never contains the full name, phone, note, network or idempotency data, or anything about other orders (FR-042 /
FR-043).

## Owner functions (authenticated; the tenant comes from `auth.uid()`)

`p_actor` = `{ name: text ≤ 80, terminal: text ≤ 40 }` is written to the history.

Each function:
1. calls `_orders_expire(auth.uid())`;
2. locks the order (`_order_owner`; returns `not_found` if not the caller's);
3. compares `state` with the allowed source states;
4. applies the change, stamps `updated_at`, writes an event;
5. returns `{ok:true, code:'ok', order:<full row>, lines:[…]}`.

Refusals return `{ok:false, code, order:<full row>}`:
- `handled`: the state is a known state but no longer the expected one;
- `expired`;
- `invalid_transition`;
- `confirm_exceeds`;
- `reason_required`;
- `all_zero`;
- `not_found`.

| Function | From | To | Extra rules |
|---|---|---|---|
| `order_accept(p_order uuid, p_expected_state text, p_lines jsonb, p_actor jsonb)` | `submitted` | `confirmed` | `p_lines` = `[{line_no, confirmed_qty, reason?}]`. Every `confirmed_qty` must be ≥ 0 and ≤ `ordered_qty`; `reason` is required when below. Lines that aren't listed are confirmed at their ordered quantity. All lines at zero → `all_zero`. Sets the confirmed totals with the same rounding as R14, and writes events `confirmed` + `adjusted` (when any line was reduced). |
| `order_reject(p_order, p_expected_state, p_reason, p_actor)` | `submitted` | `rejected` | reason 1–300 |
| `order_ready(p_order, p_expected_state, p_actor)` | `confirmed` | `ready` | |
| `order_cancel_by_shop(p_order, p_expected_state, p_reason, p_actor)` | `confirmed`, `ready` | `cancelled` (`cancelled_by='shop'`) | reason 1–300 |
| `order_complete(p_order, p_sale_global_id uuid, p_sale_total_usd numeric, p_actor)` | `confirmed`, `ready` | `completed` | Sets `sale_global_id`, `sale_total_usd` and `closed_at`. A second call with the same sale id returns `ok` (idempotent); a different sale id returns `handled`. |
| `order_complete_undo(p_order, p_sale_global_id, p_actor)` | `completed` with that sale id | the state before completion | compensation only (R20) |
| `orders_sweep()` | — | — | `_orders_expire(auth.uid())`; returns `{ok, expired:n}`. Called before each orders pull. |
| `order_blocked_phones(p_store uuid)` | — | — | lists `[{phone, note, created_at}]` for the caller's store |
| `order_block_phone(p_store, p_phone, p_note)` / `order_unblock_phone(p_store, p_phone)` | — | — | Normalises with `_order_phone`; returns `invalid` for a bad phone and `not_owner` for a store that isn't the caller's. |

`p_expected_state` is the state the user saw. The check is `state = p_expected_state AND state IN (allowed)`. If it
fails, the result is `handled` together with the current row, so the second user is told what happened (US4 AS5).

Table privileges:
- `orders`, `order_lines`, `order_events`: authenticated `SELECT` through RLS only; no `INSERT`, `UPDATE` or
  `DELETE` policy.
- `order_counters`, `order_blocked_phones`, `storefront_gateway_keys`: no policy (functions only).
- anon: nothing on any table.

## Checks file (`supabase/checks/2026-10-23_retail_ordering_s2_checks.sql`)

The checks file contains read-only queries, each expected to return the documented result:
- the tables exist with RLS enabled, and the policies are exactly the owner SELECT ones;
- the function grants match the table above;
- `transactions.order_global_id` exists;
- at least one non-revoked gateway key row exists, reported as a count only;
- no order row has a total that differs from the sum of its lines;
- no `completed` order lacks a `sale_global_id`.

## Owner setup (one-time, not in the migration)

The key is generated on the owner's machine. Only its hash goes to the cloud, so the secret never appears in the
SQL editor history. The command is `node scripts/gateway-key.mjs`: it prints a new key, to paste into Render's
`ORDER_GATEWAY_KEY`, and its SHA-256 hex, to use in the insert below. The script is new and run locally; it writes
nothing to disk.

```sql
-- Supabase SQL editor: only the hash
INSERT INTO storefront_gateway_keys (key_hash, label) VALUES ('<sha256 hex>', 'render-2026-10');
```

## Implementation notes

- Hashing uses `_order_sha256` with core `sha256(convert_to(..., 'UTF8'))`, rather than `digest`; pgcrypto is not
  required. An empty quote adds the order-level problem `empty`.
- `order_submit` also returns `invalid` with field `attempt` unless the idempotency key matches
  `[A-Za-z0-9-]{8,64}`. Successful
  `order_status` includes `code: 'ok'`.
- `order_accept` also returns `invalid` for non-array `p_lines`, or with `line_no` for a non-numeric or negative
  confirmed quantity. `order_complete` returns `invalid` when the sale id is null.
- Blocked-phone functions use envelopes: list returns `{ok:true, code:'ok', rows:[...]}`, add returns
  `{ok:true, code:'ok', phone:<normalised>}`, and remove returns `{ok:true, code:'ok'}`. Remove uses the supplied
  phone unchanged if normalisation fails, returning success rather than `invalid`.
